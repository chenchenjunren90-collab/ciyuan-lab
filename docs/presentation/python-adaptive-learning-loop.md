# Python 完整自适应学习闭环（PPT 六部分素材）

> 状态口径：本文把“已实现”和“待迭代”严格分开。运行数字应在最终验收后更新。

## 一、作品阐述

Python 被选为首版完整流程示范课程。学生不是进入一个无限问答框，而是依次完成服务器判分的
初始诊断、结构化知识学习、课程练习与代码挑战、阶段重测、画像更新和综合项目。C语言与数据
结构同步保留课程地图、RAG辅导、练习、代码验证和项目等基础能力，用于证明统一课程包可以扩展。

## 二、功能思路

1. 初始诊断从已审核题库选择八道题，前端拿不到答案，后端统一判分并生成学习证据。
2. 学情规划智能体根据掌握度和前置关系生成阶段路径，只能推荐课程包中真实存在的活动。
3. 学习资料采用项目组审核的“学习顺序—分步例题—立即检验”，AI负责解释、追问和分层提示，
   不临场生成整章教材。
4. 练习结果和代码隐藏测试结果进入画像；系统优先选择薄弱知识点生成下一道 Python 变式题。
5. 阶段重测使用与初测不同的题目，再次更新画像，形成可观察的能力变化。
6. 综合项目将数据清洗、异常处理、字典统计和模块化等计算机目标迁移到脱敏或合成财经场景。

## 三、技术方案

- 诊断：`DiagnosticService` 负责选题、隐藏答案、服务器判分与证据写入；初测和重测题集分离。
- 学习内容：版本化 YAML 课程包保存目标、前置关系、来源、学习顺序、例题、误区和检验点。
- 自适应题：`AdaptiveProblemService` 从画像选择薄弱点，以学生会话和轮次生成稳定种子，输出原创变式题。
- 判题：公开样例进入前端，三组确定性用例由服务器保管；代码交给已有 Docker 沙箱执行。
- 画像：诊断事件与 `code.verified` 事件使用同一掌握度策略投影，下一任务始终有证据依据。
- 智能体：学情规划、课程辅导、质量监督保持三个逻辑角色；大模型不参与答案键和代码正确性判定。
- 契约：新增诊断与个性化题 OpenAPI 定义，前后端共享稳定字段和错误语义。

## 四、运行效果

已完成代码级验证的能力包括：诊断题响应不泄露答案、伪造题号被拒绝、个性化题不返回隐藏测试、
题目 ID 不能跨学生会话提交、代码结果可更新画像并返回下一道变式题。前端已提供诊断答题区、
结构化学习卡和红白风格的个性化代码实验区。课程包校验、相关后端测试、类型检查与前端生产构建
均已通过；真实 Docker 浏览器全链路数据在最终本地验收后补录。

## 五、迭代计划

1. 把当前四类 Python 变式题扩展到函数、文件、模块和数据处理等更多知识点，并加入难度阶梯。
2. 增加“运行公开样例”和“提交隐藏测试”的双按钮与逐次尝试记录。
3. 将综合项目从材料记录升级为可上传制品、自动执行项目测试并生成能力证据。
4. 让RAG辅导接收脱敏后的薄弱点摘要，自动调整解释粒度，但不发送学生身份与完整画像。
5. 增加学习前后测对比、知识点停留时间和错误类型统计，供学生和教师查看。
6. 开展学生试用并用任务完成率、首次通过率和重测提升量评价效果。

## 六、创新之处

1. 用“固定教学骨架＋证据驱动适配”解决纯AI教材跳跃、结构不稳和难以复习的问题。
2. 个性化不止改变推荐列表，还改变下一道代码题的参数、边界与测试，同时保持判题可复现。
3. 初测、学习、代码验证和重测进入同一事件化画像，展示能力变化而不是一次性分数。
4. 学生侧公开内容与服务器侧隐藏测试严格分离，模型、浏览器和学生均不能改变正确性标准。
5. 财经场景只放在课程后的迁移实践，计算机课程目标和验收标准不可被模型改写。
6. 三门课程共用课程包Schema、RAG、画像和沙箱，Python完整闭环可以低成本复制到其他课程。
