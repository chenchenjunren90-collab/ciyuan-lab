# Python 个性化沉浸式学习闭环（PPT 六部分素材）

> 当前状态：本地功能实现与自动化验证已完成；真实学生试用数据与线上运行截图仍属于后续验收材料。

## 一、作品阐述

本功能面向编程基础较弱的计算机专业学生，把 Python 学习设计为“摸底—规划—动态课堂—代码验证—课后迁移—阶段重测”的连续闭环。首个可演示闭环包含“列表遍历与条件筛选”和“字典与快速查找”两课。它不是把知识包装成游戏剧情，也不是开放式 AI 闲聊，而是让林老师、助教小程和三位不同特点的同学围绕同一教学目标陪学生完成真实学习任务。计算机知识、代码能力和服务器判题始终是主线。

## 二、功能思路

1. 老师每次只讲一小段，学生主动确认后才进入下一段，不自动跳转、不设置催促倒计时。
2. 三次理解检查分别覆盖遍历、筛选和列表推导式调试；答错时由老师或同伴给方向，允许重新思考。
3. 同伴是与初学者一起学习的课堂角色：小禾敢问基础问题，阿拓喜欢共同 Debug，宁宁负责复述总结。
4. 学生可在课内或课后选择角色提问，回答必须经过 Python 课程资料检索和质量监督。
5. 随堂练习与课后作业使用服务器隐藏测试；只有代码真实通过，才能完成本节并解锁下一课。
6. 练习证据沿用学习画像服务，为后续个性化推荐和难度调整提供依据。
7. 学生可用自然语言描述学习经历、做过的任务和卡点；助教先把自述与课程先修路线匹配，再由 8 道客观题校正，避免只凭自我感觉定级。
8. “课堂完成度”和“能力掌握度”分开显示并可展开查看算法，防止把浏览进度误当成真实能力。
9. 助教依据测评证据、课程目标、用户自述、每天可用时间和“分步讲解/例题先行/先练后讲”偏好重新组合本次课堂，而不只让所有人从不同固定章节开始。
10. 练习工坊提供关键词搜索、画像推荐、预计用时排序和“继续上次”，避免学生在 80 余项练习中迷失。

## 三、技术方案

- 教学骨架：后端提供版本化课堂脚本、角色、教学节拍、白板解释、运行轨迹和公开任务，避免大模型临场生成整节教材造成跳跃。
- 智能体：仍为学情规划、课程辅导、质量监督三个逻辑智能体。老师、助教和同学只是课程辅导智能体的受控表达人格，不增加冗余自治智能体。
- RAG：Python 课程以 40 个核心知识节点、162 项细分技能和 52 条前置关系组成六阶段知识路线；检索资料覆盖基础语法、控制流、容器、函数、文件、异常、模块、类、算法、数据处理和工程实践。角色自由对话与自述画像判断都先检索课程依据，再由质量监督智能体通过讯飞模型复核语义，并以确定性规则检查引用和结论边界。
- 确定性检查：课堂选择题由服务端固定答案判定；代码练习和作业沿用隔离沙箱与隐藏测试，大模型不能宣布代码通过。
- 学习状态：首次进入课堂确保存在课程画像；练习通过后把 `code.verified` 证据投影到掌握度并返回更新后的画像。
- 前后端契约：新增课堂脚本、理解检查、课堂对话与自述画像四类 API，并同步写入公共 OpenAPI 契约。
- 画像匹配：新增自述初判 API，输出保守等级、识别线索、推荐起点和匹配知识点；自述结果只参与规划提示，客观测评和代码证据优先。
- 动态组课：前端组课器只从后端审核过的课堂节拍中选择和排序。它根据当前课程目标掌握度、自述等级、每日时间和偏好决定保留哪些讲解、是否先练后讲以及课堂环节数量，避免让模型临时编写不连续教材。
- 连续课程：同一课堂契约支持两节 Python 课。第一课作业经隐藏测试通过后，才解锁第二课；第二课继续复用画像和学习偏好，并绑定独立的字典随堂题、课后题和检查点。
- 练习推荐：用下一任务、知识点薄弱度、题目阶段、难度和预计时长形成可解释的本地排序；最近打开的练习按学生与课程分别保存。
- 视觉：Vue 单页课堂采用首经贸红、暖白、木色和墨绿白板，包含教室场景、角色发言状态、课堂进度、对话区和代码编辑区，并提供响应式布局。

## 四、运行效果

- 本地直接演示入口：`http://localhost:3000/?tab=classroom`。
- 已实现两节各 7 个连续教学节拍：欢迎、概念、同伴讨论、共同 Debug、随堂练习、课堂总结、课后作业。
- 已实现 5 个可选择的课堂角色，并保持同一课程证据与质量监督链路。
- 已实现 3 个需要回答正确才能继续的理解检查，错误选择可重试。
- 已实现 2 道随堂代码题和 2 道课后代码题；前端只显示公开样例，隐藏测试不进入课堂脚本响应。
- 编程题现在完整展示题目说明、输入格式、输出格式、边界约束、两组公开样例及样例解释，再进入代码编辑和沙箱验证。
- 已实现自然语言学习经历输入、助教课程匹配和结果回填；当前 RAG 索引同步后共有 60 个跨课程审核片段。
- 课堂初始进度从 0% 开始；完成一个环节后再按“已完成环节数 ÷ 本次环节数”增加。能力掌握度显示已测知识点平均分，并同步展示知识点数和证据数。
- 已实现真实的第二课解锁与进入流程，不再只有“下一课”文案；第二课完成后可直接阶段重测并更新画像。
- 练习工坊可检索全部 83 项现有活动，并提供画像推荐、继续上次、短时优先与课程顺序三种组织方式。
- 课程包校验、仓库契约校验、Ruff、Mypy、后端测试、前端类型检查、组件测试与生产构建均作为验收门槛。

## 五、迭代计划

1. 用真实初学者开展可用性测试，记录首课完成率、理解检查重试率、代码首次通过率和平均停留时间。
2. 把已验证的两课闭环扩展到变量、分支、函数和文件处理，并继续采用人工设计教学骨架。
3. 增加课堂笔记收藏、课下同伴讨论记录和教师端学习困难聚合，但不展示或推断敏感个人信息。
4. 将动态组课下沉为后端可审计的课程编排记录，让每次删减、重排和难度选择都能回放并供教师审核。
5. 补充无障碍键盘操作、窄屏设备实测和更细致的加载/断网恢复状态。

## 六、创新之处

1. 用“结构化教学脚本＋受控角色化对话”兼顾教材连贯性和课堂互动感，避免纯 AI 授课内容跳跃。
2. 同伴角色不是万能专家，而是接近初学者水平的共同学习者，分别承担提问、Debug 和总结三种互补作用。
3. 沉浸感来自等待、讨论、反馈和共同解决问题，而非积分、战斗或无关剧情，保证计算机专业学习不失焦。
4. 课堂中的关键进展由固定理解检查和真实代码测试驱动，大模型负责解释，不负责裁定正确性。
5. 所有自由回答均有课程来源和监督轨迹，可在展示互动自然度的同时说明知识权威与内容可追溯。
6. 个性化不是“换个开课章节”，而是让同一节课的讲解密度、例题顺序、练习起点和时间预算随证据变化，同时仍然只使用审核过的教学材料。
