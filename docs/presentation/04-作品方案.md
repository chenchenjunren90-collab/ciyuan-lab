### 一句话作品定义

词元研究所面向计算机专业学生，把能力摸底、个性化规划、结构化学习、多角色辅导、代码验证、学习画像更新和综合项目连接为一条可追溯学习闭环；大模型负责规划、解释和反馈，课程事实来自知识库，代码正确性由确定性测试判定。

### 适合封面或结尾的主标语

## PPT 02｜作品阐述：我们做的不是又一个聊天机器人

### 页面主结论

通用大模型可以回答问题，但无法独立保证课程连续、来源可信、代码正确和学习结果可追溯。

### 建议上屏文字

**从“能对话”走向“能完成学习闭环”**

- 面向计算机专业学生，而非泛化百科问答；
- 以课程知识、练习与代码证据为中心，而非无限聊天；
- 以三个职责明确的逻辑智能体协同，而非多个角色自由群聊；
- 以编译器、隐藏测试和规则引擎判定正确性，而非让模型主观评分；
- 以画像更新和下一任务推荐完成闭环，而非一次性回答结束。

### 讲解重点

强调“大模型是系统能力的一部分，不是系统本身”。作品的价值来自课程治理、学习工作流、确定性验证和可追溯证据的组合。

## PPT 03｜真实场景：计算机课程学习中的四个断点

### 页面主结论

平台聚焦四类可被系统直接处理的学习断点。

### 建议上屏文字

1. **起点不准**：平均分无法识别“后面会、前面缺”的非线性知识结构；
2. **内容不稳**：开放式 AI 容易跳跃讲解，学生难以形成稳定复习路径；
3. **答疑无据**：回答可能正确但来源不透明，也可能在多角色场景中答非所问；
4. **练习难验**：模型可以解释代码，却不应替代编译器和测试判定是否通过。

### 视觉建议

用一条断裂的学习链展示：摸底不准 → 学习内容不适配 → 问答不可信 → 代码结果无法验证 → 推荐继续失准。

### 事实边界

这一页属于作品聚焦的问题结构，不应写成“经过大规模调研发现”。真实用户访谈和量化验证将在《06-效果验证报告》中补充。

## PPT 05｜总体方案：一条由证据驱动的学习闭环

### 页面主结论

每一步都产生可核验证据，并成为下一步规划的输入。

### 建议上屏流程

能力摸底  
→ 学习画像  
→ 个性化规划  
→ 动态课堂与有来源问答  
→ 练习 / Debug / 代码提交  
→ 编译器与隐藏测试验证  
→ 质量监督与反馈  
→ 画像更新  
→ 下一任务或综合项目

### 讲解重点

- 测评答案由服务器判定，前端不持有答案键；
- 代码通过必须来自真实测试，不由模型宣布；
- 推荐不是固定课表，而是依据掌握度、前置关系、时间和偏好重算；
- 课程事实、测试结果、引用和画像更新均可追溯。

### 视觉建议

用闭环圆环，中间放一句：“学习结果不是聊天记录，而是下一步可用的证据。”

## PPT 06｜三个智能体：分工、协同、互相制约

### 页面主结论

三个后台逻辑智能体分别负责规划、辅导和监督，避免一个模型既出题、又回答、又自我评分。

| 智能体 | 输入 | 核心输出 | 明确不负责 |
| --- | --- | --- | --- |
| 学情规划智能体 | 测评、画像、前置关系、时间与偏好 | 阶段目标、课堂组合、下一任务及理由 | 不判定代码正确 |
| 课程辅导智能体 | 学生问题、课程阶段、RAG 证据、测试摘要 | 讲解、追问、分级提示、Debug 引导 | 不伪造来源，不修改画像 |
| 质量监督智能体 | 原问题、角色、回答、引用、结构与安全状态 | 通过、拒绝或降级意见 | 不改写测试事实，不生成伪引用 |

### 讲解重点

前台的林老师、助教小程和三位同学，是课程辅导智能体的五种受控表达角色，不是额外五个自治智能体。后台始终保持三个可独立测试的稳定职责。

### 视觉建议

画成三角协同：规划决定“学什么”，辅导决定“怎么讲”，监督决定“能否发布”；底部由确定性验证器提供不可覆盖的事实。

## PPT 08｜功能一：跨层级摸底，让学生诚实表达“我不知道”

### 页面主结论

测评的目的不是给学生排名，而是找到真正需要回补的前置能力。

### 建议上屏文字

- 重新测评可退出，未提交时不改变原学习画像。

### 视觉建议

左侧放一张测评题界面，右侧展示三类输入：正确、错误、我不知道；箭头指向“已掌握、需回补、证据不足”。

## PPT 09｜功能二：稳定主干图 + 162 个原子技能

### 页面主结论

系统既保持课程结构稳定，又能识别细粒度和非线性的知识断层。

## PPT 10｜功能三：不是固定课表，而是可解释的动态组课

### 页面主结论

个性化不只改变“从哪一章开始”，还改变讲解密度、内容顺序、练习起点和时间预算。

### 规划输入

- 服务器判分的测评证据；
- 历史练习和代码验证结果；
- 知识前置关系与薄弱点；
- 学生自述，但只作为保守辅助信号；
- 每天可投入时间与每周学习天数；
- 分步讲解、例题先行或先练后讲偏好；
- 本阶段学习目标。

### 规划输出

- 本次重点知识节点；
- 保留、删减或重排后的课堂环节；
- 随堂练习与课后迁移题；
- 推荐理由、引用与质量监督状态。

### 讲解重点

动态组课只组合后端已审核的教学节拍，不让模型临时生成整章教材，因此可以个性化，也能保持连续和可复现。

## PPT 11｜功能四：沉浸式专注课堂

### 页面主结论

沉浸感来自“讲一小段—思考—讨论—写代码—获得反馈”，而不是积分、战斗或无关剧情。

### 建议上屏文字

- 林老师分段主讲，学生确认后再进入下一环节；
- 课堂完成度与能力掌握度分开展示；
- 听课、交流、代码练习和课程资料共享同一学习上下文；
- 理解检查答错可重试，不自动跳转；
- 代码提交后仍锁定当前课堂结构，避免画像更新导致跳错环节；
- 页面操作有明确加载、成功、失败和下一步反馈；
- 全局提示显示 5 秒后自动淡出，连续提示重置计时。

### 当前可演示样板

两节 Python 连续课堂，每节 7 个教学节拍，覆盖列表遍历与条件筛选、字典与快速查找。

## PPT 12｜五种课堂角色，共用一条可信知识链

### 页面主结论

角色不同的是教学行为，不同的不是课程事实。

| 前台角色 | 课堂职责 | 表达边界 |
| --- | --- | --- |
| 林老师 | 小步讲解、概念确认 | 必须留下检查问题 |
| 助教小程 | 分层提示、方向引导 | 不直接泄露完整答案 |
| 小禾 | 提出初学者常见疑问 | 以共同思考为主 |
| 阿拓 | 共同 Debug | 给出可执行的小实验 |
| 宁宁 | 复述与总结 | 不虚构不存在的讨论 |

### 发布链

学生原问题  
→ 课程边界与输入安全  
→ 原问题检索  
→ 角色化回答  
→ 监督模型检查问题、回答和证据  
→ 本地引用、相关性、角色与安全门禁  
→ 放行、证据提取式降级或拒答

### 已验证证据

修复前，五角色回答 print 问题均被固定课题带偏；修复后同题连续两轮共 10 次测试全部通过。模型网络不可用时，系统仍能返回问题相关、有真实引用且角色可区分的保守回答。

## PPT 13｜功能五：模型解释，测试裁决

### 页面主结论

大模型可以帮助学生理解错误，但不能宣布代码是否正确。

### 建议上屏技术链

题目与公开样例  
→ 学生编写 C / Python 代码  
→ API 校验课程与练习归属  
→ 无网络隔离运行  
→ 公开样例 + 服务器隐藏测试  
→ 通过数、错误类型和受控输出  
→ 辅导智能体组织解释  
→ 质量监督核对反馈与测试事实  
→ 画像更新

### 确定性边界

- Python 固定 3.11 运行环境；
- C 使用固定 C17 编译环境；
- 默认关闭网络；
- 限制时间、内存、进程、文件和输出；
- 隐藏测试不下发前端；
- 模型不能覆盖编译器、解释器和测试结果。

### 典型代码任务

## PPT 17｜证据驱动画像：可解释、可审计、可替换

### 页面主结论

新分数 = 旧分数 + 证据权重 ×（证据值 − 旧分数）

| 证据类型 | 证据值 | 权重 |
| --- | --- | ---: |
| 基线测评 | 是否答对 | 0.45 |
| 普通练习 | 是否通过 | 0.25 |

### 可审计机制

- 同一事件 ID 只更新一次，保证幂等；
- 事件、画像和审计记录在同一事务内；
- 记录更新前后分数、证据数量、策略版本和原因码；
- 大模型不能直接写掌握度；
- 后续有足够匿名序列后，可用新策略版本评估 BKT 等方法，历史证据仍可回放。

## PPT 18｜安全、伦理与稳定降级

### 页面主结论

系统把“不能发送什么、不能让模型决定什么、失败后如何继续”写进工程边界。

### 四条安全线

1. **数据最小化**：外部模型不接收姓名、学号、联系方式、源代码或完整学习记录；
2. **知识授权**：只入库来源明确、允许使用的课程资料；
3. **代码隔离**：学生代码无网络、限资源、临时目录、用后销毁；
4. **输出门禁**：模型输出经过 Schema、来源、敏感信息和确定性事实检查。

### 稳定降级

- 模型不可用：显示明确降级状态，继续使用固定课程内容和证据提取式反馈；
- RAG 无证据：明确提示依据不足，不用模型常识补齐；
- 项目生成失败：回退到同知识目标的固定合成项目；
- 代码运行失败：返回编译、运行、超时或测试失败状态，不无限重试。

### 比赛材料提醒

《02-伦理与安全合规性声明》还需明确加入“AI 生成内容标识”的页面证据和团队负责人签字或盖章版本。

## PPT 22｜创新之处：六项可验证差异

### 页面主结论

创新不在于“用了几个智能体”，而在于把学习、模型和验证边界设计成可复现系统。

1. **三职责智能体，不是多聊天框**  
   规划、辅导、监督分别具有独立输入、输出和测试标准。

2. **模型解释与确定性验证双轨**  
   模型组织语言，编译器、隐藏测试和规则引擎决定代码与结构事实。

3. **稳定主干图 + 原子技能层**  
   兼顾课程治理与细粒度个性化，显式识别“后面会、前面缺”。

4. **审核教学骨架 + 证据驱动动态组课**  
   不让模型临场生成整章教材，同时允许内容密度、顺序和时间预算变化。

5. **角色化互动 + 同一可信知识链**  
   五个课堂角色行为可区分，但引用、课程边界和质量门禁完全一致。

6. **现实问题结构 + 固定合成数据**  
   公开资料提供场景结构，学生使用虚构、可复现、带哈希的数据，兼顾应用感和隐私。

### 同类方案对比建议

| 常见方案 | 词元研究所 |
| --- | --- |
| 开放式问答为主 | 测、学、练、评、画像、推荐闭环 |
| 模型同时回答和评分 | 语言模型与确定性验证分权 |
| 角色越多越“智能” | 后台只保留三个可测试职责 |
| 固定章节推荐 | 原子技能、前置断层和时间偏好共同组课 |
| 无来源或只给链接 | 引用 ID、标题、片段和执行轨迹可核验 |
| 真实敏感数据增强场景感 | 公开结构 + 固定合成数据 |

# 六、答辩高频问题准备

## 6.1 “为什么不直接用一个大模型？”

因为学习规划、课程讲解和质量监督的输入、规则与评价标准不同。拆分后可以分别测试“计划是否引用真实活动”“回答是否有来源”“输出是否与测试事实一致”，也避免同一个模型既生成答案又评价自己。

## 6.2 “为什么没有做模型微调？”

赛事推荐微调，但并非唯一实现路线。当前阶段的核心瓶颈是课程事实、工作流和代码正确性，而不是通用语言能力。项目选择 RAG、课程包、画像、工作流和确定性验证构建学科垂类能力，并通过讯飞 MaaS 统一调用模型。后续若积累经授权、质量稳定且规模足够的数据，再评估微调；当前不以小样本微调制造虚假的专业性提升。

## 6.3 “五个角色是不是为了显得智能体多？”

不是。后台只有三个逻辑智能体。五个课堂角色只是课程辅导智能体的受控表达方式，分别承担讲解、提示、提问、Debug 和总结；它们共用相同的课程证据和质量门禁。

## 6.4 “如何保证 AI 不会把错误代码说成正确？”

代码是否通过只取决于编译器、解释器和公开/隐藏测试。模型只能读取去敏后的测试摘要并解释，不拥有修改 accepted、passed_tests 或画像事实的权限。

## 6.5 “课程内容是否权威？”

系统已建立来源、版本和引用机制，课程资料可追溯；但 122 个知识点当前仍是项目组 MVP 内容，尚未完成课程教师正式审核。正式教学发布前必须增加教师审核与课程包发布流程。

## 6.6 “如何证明个性化不是换个开头？”

系统同时使用测评结果、前置断层、历史代码证据、时间预算和学习偏好，决定讲解密度、环节顺序、练习起点和下一任务；通过代码后画像更新，再重新计算后续课程。

## 6.7 “如何推广到别的课程？”

三门课程已经共用课程包 Schema、OpenAPI、RAG、画像、前端组件和智能体工作流。扩展时主要替换知识点、来源、练习、隐藏测试和项目模板，而不是复制整套系统。
