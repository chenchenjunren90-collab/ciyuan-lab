# 课程内容 v2 质量标准

## 1. 用途

本标准是 `docs/course-package-standard.md` 的教学质量补充，不改变现有
`schema_version: "0.1.0"` 数据契约。原校验器继续负责结构、引用和安全边界；
`scripts/audit_course_content.py` 负责发现“结构合法但教学内容过薄”的记录。

首期覆盖 C 语言、Python、数据结构三门课程，每门 40 个核心知识点。平台中心始终
是计算机专业能力，财经管理背景只能进入课程后的综合项目，不能替代课程原理、代码
和算法训练。

## 2. 单个知识点的最低质量线

每个知识点应当做到：

1. 至少 2 条可观察、可测量的学习目标；
2. `lesson.summary` 不少于 60 个非空白字符，说明概念、作用和适用边界；
3. 至少 3 条有知识点针对性的 `key_points`；
4. 至少 1 个可以直接阅读或运行的 `examples`；
5. 至少 2 条与本知识点直接相关的 `common_mistakes`；
6. 至少关联 1 道练习和 1 个已登记来源；
7. 准备发布时，知识点、练习及来源均应经人工审核，RAG 来源应标记为
   `reviewed` 且 `rag.eligible: true`。

“先说明适用前提”“忽略输入边界”等可以作为教学原则，但不得在大量知识点中代替
具体讲解。审计脚本会把在同一课程内重复出现 8 次及以上的教学条目标记为模板化内容。

## 3. 练习与项目要求

- 每个知识点至少有一道确定性练习；
- 每门课程至少 8 个知识点由代码题或 Debug 题覆盖；
- 核心章节应同时包含概念判断、代码实现或 Debug，而不是全部使用同一种客观题；
- 每门课程至少一个综合项目，必须支持提交、确定性验证和评价反馈；
- C 语言项目优先考查语法、指针、内存、文件与调试，不强行财经化；
- Python 和数据结构可以在课后项目中使用经授权、脱敏或合成的经管场景，但评分核心
  仍然是程序设计、数据处理和算法能力。

## 4. 来源与 RAG 要求

- 每个知识点至少有一个可核验来源；
- 来源必须记录定位信息、权利依据、数据分类和审核状态；
- 只有 `reviewed` 且 `rag.eligible: true` 的正文进入正式知识库；
- 正式知识库目标不少于 120 个知识片段，并保留 `course_id`、`concept_id`、
  `source_id`、版本和片段位置；
- 回答必须课程隔离并返回来源；低相关度、跨课程或知识库外问题应明确依据不足；
- 合成资料必须明确标记为合成内容，不得伪装成教材、学校案例或官方结论。

## 5. 人工审核边界

自动审计只能检查长度、数量、重复度、引用和状态，不能证明知识正确、讲解清晰、来源
授权真实或题目难度合理。课程从 `draft` 转为 `reviewed` 前，仍需课程负责人逐条复核，
成员 1 抽查代表性知识点、代码题隐藏测试、来源证据和完整学习路径。

## 6. 使用方式

生成可提交的 Markdown 基线报告：

```powershell
python scripts/audit_course_content.py --output docs/audits/course-content-v2-baseline.md
```

输出机器可读 JSON：

```powershell
python scripts/audit_course_content.py --format json
```

内容全部补齐后，可在 CI 或发布验收中使用严格模式：

```powershell
python scripts/audit_course_content.py --fail-on-gaps
```
