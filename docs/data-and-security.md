# 数据、模型与安全边界

## 1. 原则

初步版本遵循最小数据、明确授权、来源可追溯、外部调用可替换、代码执行强隔离。演示方便不能成为绕过权限、脱敏和验证的理由。

## 2. 数据分类

| 级别 | 示例 | 处理要求 |
|---|---|---|
| D0 公开 | 开源许可课程资料、公开合成数据 | 记录来源与许可后可入库 |
| D1 项目授权 | 校内课程大纲、教师授权讲义、授权案例 | 限项目使用，按授权范围检索和展示 |
| D2 受限学习数据 | 匿名用户ID、练习记录、掌握度 | 最小化采集、访问控制、日志脱敏 |
| D3 禁止进入初步版本 | 姓名学号映射、联系方式、原始金融主体/账户数据、密钥 | 不采集、不上传模型、不提交仓库 |

学生记录使用随机内部ID；确需展示身份时由前端会话层映射，外部模型请求中不携带姓名、学号和联系方式。

## 3. RAG边界

- 只入库来源明确、允许使用的资料；
- 保存 `source_id`、标题、版本、章节/页码、授权状态和入库时间；
- 检索片段与最终引用建立可核验关联；
- 提示词要求模型仅依据上下文回答，但仍需程序校验引用是否存在；
- 低相关度、冲突或无资料时返回“依据不足”，可建议查看课程资料或请教师确认；
- 删除或撤销授权的资料要能从原文、索引和缓存中同步移除。

## 4. 模型调用边界

所有模型调用经过 `apps/api/app/modules/model_adapters/`：

- 凭据只来自运行环境或密钥服务，不写入代码、课程包和日志；
- 请求设置超时、有限重试、并发/配额控制和熔断；
- 发送前删除身份字段、秘密、无关历史和未授权原文；
- 输出先通过JSON Schema、长度和敏感内容检查；
- 记录模型提供方、用途、耗时、状态和去敏摘要，不记录完整敏感提示词；
- 模型不可用时使用固定学习内容、检索结果和确定性测试反馈降级。

## 5. 合成财经项目使用边界

财经场景不是通用财经咨询功能，只用于课程后的计算机综合练习：

- 只参考权利明确的公开资料结构，练习主体、编号、时间和数值均为本地固定合成；
- 外部模型只接收非身份化学习目标、薄弱知识点和已审核项目模板；
- 计算机课程智能体负责技术指导，确定性程序负责代码验证；
- 模型只能调整任务表述和难度，不能改变计算机知识目标、伪造来源或输出完整代码；
- 输出不得用于真实投资、信用、营销、经营或合规判断；
- 模型不可用或输出未通过 Schema、来源白名单与敏感信息检查时，使用固定项目降级。

## 6. 代码执行边界

学生代码按不可信代码处理：

- 容器/进程隔离，默认关闭网络；
- 只读基础环境，临时工作目录用后销毁；
- 限制CPU、内存、运行时间、进程数、文件大小和输出长度；
- 固定C编译器、Python版本和依赖白名单；
- 禁止访问宿主凭据、数据库、容器控制接口和其他用户文件；
- 测试结果由运行器产生，模型只接收必要的去敏摘要；
- 超时、崩溃和输出超限作为明确状态返回，不无限重试。

三周初步版本若无法实现可靠隔离，则仅执行团队维护的固定样例或使用外部受控判题服务，不在后端宿主机直接运行任意代码。

## 7. Web与接口基本要求

- 服务端校验身份、权限、资源归属和所有输入，前端校验不能替代；
- 数据库使用参数化查询，模型输出不得拼接为SQL或命令；
- 对模型提示、检索查询、代码提交和登录接口限流；
- HTML/Markdown输出安全渲染，阻止脚本注入；
- 错误响应不暴露堆栈、内部路径、查询语句和厂商凭据；
- 演示数据与开发数据分开，提交前执行秘密与个人数据扫描。

## 8. 上线/演示前检查

- [ ] 外部资料授权与来源台账完整；
- [ ] `.env`、密钥、真实用户数据未进入Git历史；
- [ ] 模型请求样例已确认无身份字段；
- [ ] 财经场景明确标记为课后综合练习，数据为固定合成且来源可追溯；
- [ ] 代码运行的超时、网络和资源限制实际生效；
- [ ] 提示注入、越权读取、伪造引用和模型不可用均有测试；
- [ ] 有停用外部模型和切换Mock/固定内容的开关。
