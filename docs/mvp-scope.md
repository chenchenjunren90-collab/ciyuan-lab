# MVP范围与验收边界

本文件只定义当前版本要达到的结果和验收边界，岗位边界以 [六人岗位分工与协作者执行说明](responsibilities.md) 为准，具体任务以 [协作者 Issue 执行手册](collaborator-issues.md) 为准。

## 目标结果

评审者能够选择C语言、Python或数据结构，完成一次从初始测评、个性化计划、课程学习、练习或Debug、代码验证到画像更新和下一任务推荐的完整流程，并查看课程知识来源与确定性验证结果。

## 纳入范围

- C语言、Python、数据结构各建立约40个核心知识点的结构化目录；
- 每个知识点具有稳定ID、学习目标、前置关系、难度、来源和测评映射；
- 每门课程选择8—12个重点知识点制作完整学习卡、练习、Debug或代码任务；
- 三门课程共用课程包Schema、前端组件、后端流程、RAG和画像机制；
- 实现学情规划、课程辅导、质量监督三个逻辑智能体的可区分职责；
- RAG回答返回可核验来源，依据不足时明确降级；
- 代码结论由编译、运行、测试和规则确定，模型只解释结果；
- 支持模型Mock与失败降级，外部模型不可用时核心流程仍可演示；
- 财经元素只用于课后综合练习；公开资料提供问题结构，实际练习使用可复现的固定合成数据。

## 不纳入范围

- 模型权重训练、预训练或跨课程批量训练；
- 生产级高并发、计费、社交和排行榜；
- 全校所有课程或完整培养方案覆盖；
- 未经授权的真实学生数据、财经数据和课程资料；
- 为三门课程分别复制前端、后端或智能体；
- 以大模型主观判断替代代码测试和人工内容审核。

## 版本完成条件

- 六个角色主责的 Issue 均有明确负责人和验收证据；普通成员 PR 由成员1统一审核合并，成员1自己的 PR 留下完整自检证据；
- 三门课程至少各有一条完整学习流程可复现；
- 公共契约、课程包校验、后端测试和前端检查通过；
- 正常、失败、超时、依据不足和模型降级路径均有验证；
- 不含密钥、真实个人信息、未授权资料和未脱敏数据；
- 从新环境可以按照README启动；若存在环境限制，必须在发布Issue中如实记录。

## 范围变更

新增需求必须建立Issue，并说明它是否直接服务上述完整流程、能否复用现有模块以及需要放弃什么现有范围。未经Issue确认的口头需求不进入当前版本。

当前路线使用讯飞 MaaS 托管模型推理、授权知识库、RAG、学习画像与确定性代码验证；可按服务配置接入 MaaS 文档重排。知识版本、服务标识、调用效果和人工内容审核记录应进入竞赛证据材料。已实现的接口能力和已完成的真实服务验收必须分别记录。
