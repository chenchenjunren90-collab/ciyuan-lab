# 系统架构

## 1. 架构目标

初步版本采用“前后端分离 + FastAPI模块化单体 + 三个逻辑智能体 + RAG/数据库/确定性代码验证”的结构，优先保证完整学习流程、课程一致性和可审核性。

![总体架构图](assets/architecture-v0.3.png)

## 2. 学生学习流程

```text
初始测评
  → 生成当前知识画像
  → 学情规划智能体制定阶段计划
  → 学生学习课程内容并提问
  → 课程辅导智能体基于RAG讲解和引导
  → 学生完成练习、Debug或综合项目
  → 编译/测试/规则引擎给出确定性结果
  → 质量监督智能体检查依据、安全和反馈一致性
  → 更新画像并推荐下一任务
```

“完整学习流程”指从识别学生当前能力开始，到学习、实践、验证、反馈、画像更新和下一步推荐结束的一次闭环，不代表必须在初步版本中覆盖所有课程内容和生产场景。

## 3. 分层结构

| 层次 | 组成 | 职责 |
|---|---|---|
| 交互层 | `apps/web/` | 课程浏览、对话、代码编辑、反馈和画像展示 |
| API层 | `apps/api/` | 认证边界、请求校验、统一错误、流式响应 |
| 编排层 | `modules/orchestration/` | 按学习状态路由三个逻辑智能体，控制流程而非自由群聊 |
| 业务层 | `learner_profile/`、`practice/`、`rag/` | 画像与计划、练习与验证、知识检索与引用 |
| 模型层 | `model_adapters/` | 讯飞 MaaS 适配、超时、重试、结构门禁与 Mock 降级 |
| 数据层 | PostgreSQL/pgvector、Redis、课程包 | 结构数据、向量检索、短期状态和版本化内容 |
| 验证层 | 代码运行器、测试、Schema校验 | 独立于模型验证代码与结构化输出 |

## 4. 三智能体协同

### 学情规划智能体

输入包括基线测评、知识点掌握度、历史练习和课程目标；输出为结构化的阶段计划与推荐理由。计划只能引用现有知识点ID，不能生成不存在的课程内容。画像更新由业务规则落库，并保留更新依据。

### 课程辅导智能体

根据课程、知识点、学生水平和RAG片段提供解释、递进提示、错误定位与拓展题。默认采用引导式反馈而非直接给出完整答案；引用不足时明确提示，而不是使用无来源事实补齐。

### 质量监督智能体

在输出前后执行检查：任务是否路由正确、结构是否符合Schema、引用是否存在、敏感信息是否泄露、代码测试结果是否被准确解释。它可以要求重试、降级或转为固定模板，但无权修改确定性测试结果。

### 为什么需要三个而不是一个

规划、教学和监督分别使用不同输入、规则和评价标准。拆分后可独立测试“计划是否合理”“讲解是否有依据”“输出是否安全一致”，同时保持仅三个稳定职责，避免为了多智能体而增加无意义对话。

## 5. 模型和知识路线

- 通用讲解、计划草案、反馈与受控项目编排：通过统一适配层调用讯飞星辰 MaaS 托管的 DeepSeek-V4-Flash-0731；
- 课程事实：由授权课程资料构建RAG索引，返回资料、章节或片段标识；
- 学习状态：数据库记录，不依赖模型记忆；
- 代码结论：编译器、解释器、隐藏测试和规则引擎确定；
- 财经综合练习：参考 UCI、CFPB、IBM AMLSim 等公开结构，本地生成固定虚构数据；
- 本阶段不做微调，所有差异化能力来自课程包、RAG、工作流、学生画像和验证机制。

## 6. 关键请求示例

一次代码练习提交的处理顺序：

1. API校验用户、课程、知识点与练习ID；
2. `practice` 在隔离环境执行代码与测试；
3. 得到通过情况、错误类型和受控输出；
4. `rag` 检索相关知识点资料；
5. 课程辅导智能体结合测试事实与检索片段组织反馈；
6. 质量监督智能体检查引用和反馈是否与测试一致；
7. `learner_profile` 按规则更新掌握度并推荐下一任务；
8. 返回结构化结果，前端展示证据、提示和下一步。

## 7. 可扩展方向

初步版本稳定后，可按实际数据决定是否增加课程、丰富知识图谱、接入教师审核后台、引入更复杂的项目实训。只有在独立扩容、故障隔离或团队边界形成明确需求时，才考虑从模块化单体拆分服务。
