# 系统架构

## 1. 架构目标

初步版本采用“前后端分离 + FastAPI模块化单体 + 三个逻辑智能体 + RAG/数据库/确定性代码验证”的结构，优先保证完整学习流程、课程一致性和可审核性。

![总体架构图](assets/architecture-v0.3.png)

## 2. 学生学习流程

```text
初始测评
  → 生成当前知识画像
  → 学情规划智能体制定阶段计划
  → 学生学习课程内容并提问
  → 课程辅导智能体基于RAG讲解和引导
  → 学生完成练习、Debug或综合项目
  → 编译/测试/规则引擎给出确定性结果
  → 质量监督智能体检查依据、安全和反馈一致性
  → 更新画像并推荐下一任务
```

“完整学习流程”指从识别学生当前能力开始，到学习、实践、验证、反馈、画像更新和下一步推荐结束的一次闭环，不代表必须在初步版本中覆盖所有课程内容和生产场景。

## 3. 分层结构

| 层次 | 组成 | 职责 |
|---|---|---|
| 交互层 | `apps/web/` | 课程浏览、对话、代码编辑、反馈和画像展示 |
| API层 | `apps/api/` | 认证边界、请求校验、统一错误、流式响应 |
| 编排层 | `modules/orchestration/` | 按学习状态路由三个逻辑智能体，控制流程而非自由群聊 |
| 业务层 | `learner_profile/`、`practice/`、`rag/` | 画像与计划、练习与验证、知识检索与引用 |
| 模型层 | `model_adapters/` | 讯飞 MaaS 适配、超时、重试、结构门禁与 Mock 降级 |
| 数据层 | PostgreSQL/pgvector、Redis、课程包 | 结构数据、向量检索、短期状态和版本化内容 |
| 验证层 | 代码运行器、测试、Schema校验 | 独立于模型验证代码与结构化输出 |

## 4. 三智能体协同

### 学情规划智能体

输入包括基线测评、知识点掌握度、历史练习和课程目标；输出为结构化的阶段计划与推荐理由。计划只能引用现有知识点ID，不能生成不存在的课程内容。画像更新由业务规则落库，并保留更新依据。

### 课程辅导智能体

根据课程、知识点、学生水平和RAG片段提供解释、递进提示、错误定位与拓展题。默认采用引导式反馈而非直接给出完整答案；引用不足时明确提示，而不是使用无来源事实补齐。

### 质量监督智能体

先以确定性规则检查任务路由、Schema、引用、安全和测试一致性，再通过讯飞 MaaS 模型复核证据支持程度、教学难度匹配和答案泄露风险。模型只能给出通过或拒绝意见，不能改写回答、生成引用、修改代码判题事实或覆盖学习画像；模型不可用或输出不合规时，系统明确标记降级并继续执行不可绕过的规则门禁。

### 为什么需要三个而不是一个

规划、教学和监督分别使用不同输入、规则和评价标准。拆分后可独立测试“计划是否合理”“讲解是否有依据”“输出是否安全一致”，同时保持仅三个稳定职责，避免为了多智能体而增加无意义对话。

## 5. 模型和知识路线

- 学情规划、质量监督与受控项目编排：通过统一适配层调用讯飞星辰 MaaS 托管的 DeepSeek-V4-Flash-0731；
- Python 课程辅导：在经人工审核和 MaaS 评测通过后，可调用独立的 SFT/LoRA 垂类模型；未启用时回退至 DeepSeek，C语言和数据结构保持通用模型；
- 课程事实：优先由授权课程资料构建RAG索引；本地无证据且问题明确属于 Python 时，最多读取两页 `docs.python.org` 白名单资料并返回可核验网址；
- 学习状态：数据库记录，不依赖模型记忆；
- 代码结论：编译器、解释器、隐藏测试和规则引擎确定；
- 财经综合练习：参考 UCI、CFPB、IBM AMLSim 等公开结构，本地生成固定虚构数据；
- Python 微调只学习教学角色、分层提示、Debug 引导和结构化输出；所有课程事实、代码结论、引用和学习画像仍来自课程包、RAG、工作流和验证机制。

## 6. 关键请求示例

一次代码练习提交的处理顺序：

1. API校验用户、课程、知识点与练习ID；
2. `practice` 在隔离环境执行代码与测试；
3. 得到通过情况、错误类型和受控输出；
4. `rag` 检索相关知识点资料；
5. 课程辅导智能体结合测试事实与检索片段组织反馈；
6. 质量监督智能体检查引用和反馈是否与测试一致；
7. `learner_profile` 按规则更新掌握度并推荐下一任务；
8. 返回结构化结果，前端展示证据、提示和下一步。

## 7. 课堂角色对话发布链

林老师、助教小程及三位同学是课程辅导智能体的受控角色。前端随本轮问题携带最多
8 条最近对话用于消解“这个、刚才、这一步”等指代，但课程事实仍必须来自 RAG：

1. 原问题先经过输入安全和课程隔离，固定课堂主题不能覆盖学生意图；
2. 优先直接检索原问题；只有指代式问题且存在最近对话时，才允许上下文检索；
3. 本地检索为空时，只有带明确 Python 信号的问题才可触发官方文档联网检索；其他课程、通用闲聊和不明确问题不会联网；
4. 联网检索器固定为 `https://docs.python.org/zh-cn/3.11/`，本地选择页面、最多读取两页、不跟随任意外链；
5. 课程辅导输出结构化答案和真实片段 ID；
6. 质量监督同时检查学生问题、课堂角色、阶段、回答与证据；
7. 本地门禁再检查引用白名单、主题相关性、角色行为、长度和敏感内容；
8. 不合格的生成式回答不会直接展示，可替换为问题相关的证据提取式回答；替代回答仍不合格则拒答。

可复用回归脚本与修复前后证据见
[`quality/classroom-role-agent-regression.md`](quality/classroom-role-agent-regression.md)。

## 8. 可扩展方向

初步版本稳定后，可按实际数据决定是否增加课程、丰富知识图谱、接入教师审核后台、引入更复杂的项目实训。只有在独立扩容、故障隔离或团队边界形成明确需求时，才考虑从模块化单体拆分服务。
