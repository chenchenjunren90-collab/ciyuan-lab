# 词元研究所作品六部分说明

> 本文档随功能PR持续更新，作为后续竞赛PPT、技术报告和演示讲稿的统一素材来源。
> 只记录已经实现且具有可复现证据的内容；规划功能必须放在“迭代计划”，不能写成已完成。

## 一、作品阐述

“词元研究所”是面向首都经济贸易大学计算机专业学生的多智能体助学服务平台，以C语言、
Python和数据结构三门课程为初步范围。平台围绕“测评—规划—学习—练习/Debug—确定性
代码验证—画像更新—综合项目”形成闭环。计算机专业学习始终是核心，财经元素只进入
课程学习后的综合项目，用于帮助学生把编程、算法和数据处理能力迁移到现实问题结构中。
首版选择 Python 展示“初测—学习—练习—重测—新题—项目”的完整闭环，C语言和数据结构
保留统一的基础功能。

## 二、功能思路

平台由三个职责明确的逻辑智能体协同：学情规划智能体依据掌握度和前置关系安排学习路径；
课程辅导智能体基于RAG证据进行解释、追问和分级提示；质量监督智能体检查引用、输出格式、
敏感信息和降级状态。综合项目从已审核模板出发，根据学生目标和薄弱知识点调整任务难度，
但不改变课程知识目标。代码结论始终由编译器、测试用例和隔离执行环境确定。
重点知识学习采用项目组审核的固定教学骨架，不用大模型临场生成整章教材；模型只在已审核内容
和检索证据范围内调整解释、提示与反馈。

## 三、技术方案

- 前端：Vue 3、TypeScript、Vite；
- 体验：红、白、深灰代码实验室视觉，支持知识搜索、练习筛选、状态反馈与桌面/移动响应式布局；
- 后端：FastAPI模块化单体，公共接口由OpenAPI契约约束；
- 数据：PostgreSQL保存课程版本、学习事件和画像，pgvector支持RAG检索；
- 模型：讯飞星辰MaaS托管的DeepSeek-V4-Flash-0731，经统一适配层调用；
- 知识：课程包YAML作为版本化事实来源，RAG回答返回来源ID并在证据不足时拒答；
- 实践：Docker隔离运行C/Python代码，限制网络、时间、内存和输出；
- 自适应：服务器判分初测与重测；Python按画像薄弱点生成确定性变式题，隐藏测试不下发前端；
- 财经场景：参考UCI、CFPB、IBM AMLSim等公开结构，本地生成固定虚构数据；
- 安全：不向外部模型发送学生身份、源代码或完整学习记录，模型输出先经Schema和来源白名单校验。

## 四、运行效果

当前完整演示版本包含 C语言42个、Python40个、数据结构40个核心与扩展知识点，支持能力基线、学习路径、有来源问答、三级
提示、客观题、代码题、Debug、画像更新和综合项目证据记录。Python新增服务器判分的初测与
重测、结构化分步学习卡，以及“薄弱点选题—隐藏测试—画像更新—下一题”的个性化循环。新增信用还款质量审计、银行
营销统计、金融投诉统计和合成交易网络分析场景；未配置外部模型时可以使用固定合成版本
完成演示。学生端已升级为红白代码学习界面，桌面与移动端均通过真实浏览器交互检查。
课程包校验、后端全量测试、静态检查和75问RAG回归均已通过；生产环境已接入讯飞 MaaS
并完成真实问答、规划与项目生成验证，公网演示地址已部署。真实学生试用仍属于待验收事项。

## 五、迭代计划

1. 完善多轮课程对话、上下文压缩和歧义澄清；
2. 增加合成数据下载、项目生成历史和教师可查看的证据摘要；
3. 完成至少三个典型问题的端到端准确性报告；
4. 邀请至少两名计算机专业学生试用并记录时长、任务完成情况和结构化反馈；
5. 录制三分钟真实交互演示并整理提交材料；
6. 扩充 Python 变式题模板，并把综合项目证据记录升级为自动项目测试。

## 六、创新之处

1. 多智能体不是简单并列聊天机器人，而是把规划、辅导和质量门禁分成可验证职责；
2. 语言模型不直接判断代码正确性，形成“模型解释—确定性验证—可追溯反馈”的双轨机制；
3. 课程知识、来源、题目、隐藏测试和综合项目使用统一版本化课程包，便于扩展到更多课程；
4. 个性化综合项目在已审核模板内生成，计算机目标不可被模型修改，伪造来源自动降级；
5. 公开财经数据只用于抽取真实问题结构，演示数据固定合成并带哈希，实现现实感与隐私安全兼顾；
6. 平台结合首经贸“AI服务经管”的特色，但保持计算机专业助学主线，形成差异化而不转移重心。
7. 用审核过的教学骨架保证连续性，再用真实学习证据调整路径、提示与新题，避免纯AI教材的跳跃性。
