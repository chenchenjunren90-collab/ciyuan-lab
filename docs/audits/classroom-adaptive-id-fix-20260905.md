# 自适应课堂兼容性与中断恢复检查 · 2026-09-05

## 原因与影响

线上 `GET /api/v1/classroom/lessons/python-adaptive--PY-BASE-01` 返回 404，错误为 `adaptive classroom lesson id is invalid`。课堂生成器按每天时间预算安排 1、2、3 个知识点，但 ID 解析器仍要求正好 2 个。默认 30 分钟生成的单知识点课堂，以及超过 70 分钟的三知识点课堂，都会在提问、恢复课堂、自述评估和理解检查时失败。问题发生在模型调用之前。

前端先将学生问题加入对话并清空输入，失败后只把错误放在黑板下方，导致右侧呈现连续问题却没有回复，且原问题不方便重试。

用户后续截图确认了完整现象：完成客观测评与学习倾向评估后进入课堂，第一道理解检查失败，随后进入“暂时没能进入教室”的恢复失败页面。截图中的账户和课程仍在，属于课堂载入失败，不是账户被登出。未取得当时的浏览器日志，因此不能断言是哪一次导航或重载触发了组件重新挂载。

本地提交 `08d4b43` 中已经同时存在按时间生成 1–3 个知识点和解析器只接受 2 个的代码。不能把这一后台缺陷归因于后来接入的 GitHub 前端。此前验收没有覆盖默认 30 分钟生成后再访问理解检查、提问、恢复这条完整链路。

## 修复

- 校验器接受生成器支持的 1–3 个知识点；继续拒绝空项、重复项、超长列表与课程外或不存在的知识点。
- 保持原有课堂 ID 和存储格式，修复后既有单知识点、三知识点课堂可以直接恢复，不需要清空学习记录。
- 右侧互动区直接显示可操作的中文失败提示，恢复问题文本并提供“重试发送”。重试不重复添加学生消息，也不把同一个问题再次塞入历史上下文。
- 回复期间显示处理状态并锁定输入；卸载课堂或载入其他课堂后，过期回复不会进入新的课堂。
- 重新载入同一课程时保留正在挂载的课堂；后台学情同步失败单独显示重试提示，保留已保存的课堂环节与草稿。
- “重新准备”重新执行完整初始化和本地进度恢复，避免只载入课程而回到第一步；恢复失败期间不覆盖原来的存档。
- 恢复已锁定的课堂时按保存的环节顺序定位，避免新生成顺序不同造成跳步；未发送的问题和提问角色也加入兼容旧存档的可选字段。
- 重新测评先取得新题目再切换状态；获取失败保留当前课堂，取消或稍后继续重测保留选项与题号。
- 理解检查和代码提交期间禁止切换课堂环节；离开组件后的响应不再写入下一次课堂安排或触发画像更新。
- 代码验证服务不可用时保留已有能力画像；请求失败后清除残留的“正在运行”提示，代码草稿和重试入口保留。
- 本次范围：课堂编排模块、对应 API 测试、App 课堂挂载条件、Python 课堂组件、代码任务组件、课堂存档辅助函数及其测试。不变更公共契约、数据库结构、依赖、模型配置或课程内容。
