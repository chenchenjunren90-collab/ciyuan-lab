审查日期：2026-09-05。对象：ciyuan-lab 当前工作区。结论基于源代码、课程资料、离线回归，以及当日实际打开的赛事主页、赛事链接的 FAQ、MaaS 官网与官方接口文档。

现有模块化后端适合继续作为计算机学科助学应用：诊断、规划、课程辅导、确定性练习和画像更新已经形成完整路径。当前不能据此认定已达到正式教学或真实多用户部署标准。最紧迫的缺口是知识覆盖与教师审核、可靠的效果证据、身份权限，以及真实数据库和平台服务验收。

## 1. 赛题要求与当前对应关系

赛事采用推荐平台或其他工具开发，列出的技术手段允许按场景组合；前四项是必需功能，后四项为鼓励拓展。因此，托管模型结合专属知识、检索、工作流和验证的路线有依据。作品仍需证明形成了专业能力，单纯接上通用聊天接口不足以证明适配。[赛事主页](https://ai.fifedu.com/agent/landings/HomeCompetition)

| 要求 | 当前后端证据 | 判断与下一项验收 |
| --- | --- | --- |
| 真实学科场景 | 三门计算机课程、服务端诊断、课堂、练习和项目入口 | 场景成立；用教师与学生实际任务验证，财经仅保留为课后应用背景 |
| 自然交互与上下文 | 多轮课堂、角色、上下文补检索、歧义处理与友好降级 | 工程路径已覆盖；真实模型仍需盲测角色一致性、纠错与追问 |
| 可信的结构化知识 | 来源登记、权利与审核过滤、课程包结构、内容哈希 | 结构成立但资料不足；不能把技术复核等同于课程教师审定 |
| 可核查的出处 | source_id、chunk_id、来源元数据、引用白名单和监督门禁 | 可追踪片段身份；还需逐条核查引用是否真正支持答案中的结论 |
| 可复制推广 | 模块化单体、三课共用契约、迁移和容器配置 | 有复用基础；缺身份权限、真实环境恢复演练与并发证据 |
| 多样内容生成 | 多角色教学、结构化学习卡、受控综合项目 | 已有入口；应证明输出多样而事实与边界稳定 |
| 复杂任务求解 | 项目拆分、递进提示、代码确定性验证、三智能体协作 | 有流程；展示完整任务，而不是孤立问答截图 |
| 个性化适配 | 服务端诊断、证据画像、薄弱点推荐、自适应练习 | 已修正自述与客观成绩混用；尚无真实学习效果实验 |

官方评分分配为：完成度10、创意实用20、技术实现20、先进性10、内容质量20、商业潜力10、用户认可10；另有50人以上使用证据的最高10分加分。知识质量、稳定闭环和用户验证，比继续堆砌模型能力名称更直接对应评分。[赛事主页](https://ai.fifedu.com/agent/landings/HomeCompetition)

交付还需要可访问 Demo 与说明、100MB以内 PPT、可复现代码及模型文件或 ServiceID、至少三个典型问题的准确性论证、至少两位真实目标用户的反馈或结构化记录，以及三分钟以内的真实交互演示。伦理声明须按要求签字或盖章，界面应明显标注 AI 生成内容，反馈材料不得暴露未脱敏个人信息。[赛事主页](https://ai.fifedu.com/agent/landings/HomeCompetition)、[赛事官方链接的 FAQ](https://my.feishu.cn/wiki/ZbgrwHIaTizLFJkv5UMcSrVrnJr)

资料扩充应先围绕真实课程任务建立“知识点—易错认识—可引用依据—例题—验证题”映射，补齐 C 与数据结构。引入授权教材、官方文档或教师原创讲义时，登记出处、版本、许可和审核人；保留待审核状态直至教师确认。技术检查通过不能自动改为人工审核通过。

评测应增加独立保留的答案级问题，例如三课各20题，覆盖概念、Debug、错误纠正、多轮歧义、课程边界和完整答案索取。分别检查事实覆盖、引用支持、角色、边界、确定性测试一致性与延迟，并由教师盲评。该题量是工程建议，不是赛事规定。

## 4. 已落地的 MaaS 深度接入

当前规划、辅导、监督共用讯飞托管模型适配器及推理并发限制。本次新增 MaaS Rerank 适配与 RAG 包装器，接入课程问答和课堂证据检索。服务只对本课程已经召回的候选返回排序；本地验证索引、类型、唯一性及有限分数，保留原文、来源、片段ID和原始检索分数。空问题、空候选不发请求，超长片段不截断送出，失败保留原检索结果并记录降级。

该功能默认关闭，需填实际重排服务卡的 modelId 和对应授权后开启；不能用聊天模型ID替代。它已通过模拟 HTTP 与业务回归，尚未完成账户服务联调。配置与使用边界见 [接入说明](../provider-integration.md)，协议依据为 [讯飞 Embedding/Rerank 官方文档](https://www.xfyun.cn/doc/spark/Embedding%26Rerank%E6%9C%8D%E5%8A%A1_HTTP%E5%8D%8F%E8%AE%AE.html)。

进一步接入建议按以下顺序验收：

| 顺序 | 具体工作 | 完成依据 |
| --- | --- | --- |
| 1 | 对真实课程案例开启 MaaS 重排做同题对照 | 比较原检索与重排的排名、引用支持、总延迟、失败率和实际用量；没有质量增益就不默认开启 |
| 2 | 接入 MaaS 语义 Embedding | 按实际模型维度建立新索引，记录模型/维度/知识版本，全量重建并评测；不得截断远程向量塞进旧384维列 |
| 3 | 建立可追溯的平台运行证据 | 保存脱敏任务、服务标识、模型版本、知识版本、执行结果、耗时、费用与降级；导出用于典型案例论证 |
| 4 | 需要时使用平台评测能力 | 先核对账户中的可用产品与数据格式，沿用独立保留问题和人工标准；平台分数不替代教师结论 |
| 5 | 有明确收益再发布 Agent 工作流 | MaaS 与星辰 Agent 是不同平台；当前三智能体由本地后端编排，尚未发布为平台工作流 |

MaaS 官网同时展示托管推理、批量推理和评测等能力，可作为平台结合方向；本次不把官网能力列表当作本账户已开通服务的证明。[MaaS 官网](https://training.xfyun.cn/overview)

业务数据库和 Redis 继续由应用管理，学生身份与完整日志不应上传给模型平台。深度结合平台应体现在检索质量、教学任务执行与可复现证据上，不要求把所有数据库搬到平台。托管推理协议见 [官方 HTTP 文档](https://www.xfyun.cn/doc/spark/%E6%8E%A8%E7%90%86%E6%9C%8D%E5%8A%A1-http.html)。

## 5. 尚不能宣布完成的事项

- **真实多用户权限**：请求中的 student_id 不是登录身份，按ID分区不等于授权。正式对外开放真实用户前，需身份验证与资源归属检查，并做跨用户访问回归。
- **真实数据库验收**：本轮未检查线上连接、迁移版本、实际入库行数、备份恢复或查询计划。现有混合 SQL 对课程内候选计分后排序，有 HNSW/GIN 索引不代表实际利用近似近邻召回；扩库后应查看执行计划。语句超时也不等于整个请求总时限。
- **索引治理**：知识表已有引用与内容哈希，但没有独立的来源版本、审核状态、Embedding 模型版本列；撤销资料须同步索引。后续应把许可撤销、重建、切换和回滚纳入同一流程。
- **学习服务数据库访问**：本次针对 RAG 移除了同步 SQL 对事件循环的阻塞；学习画像等路径仍使用同步仓储，后续并发验收时需统一检查，不能宣称全后端已异步化。
- **线上模型与容器**：未运行真实 MaaS 请求和真实容器对抗用例，未验证线上预算、时延与资源限制，不把离线测试等同于上线验收。
- **真实教学成效**：至少两名用户、三个典型任务和对比证据仍需实际采集；不能生成虚构反馈、教师审核意见或效果数据。

建议首先打通三个可录制案例：Python异常定位与错误认知纠正、C语言代码验证与安全降级、数据结构分步求解与画像变化。每个案例提供任务输入、支持片段、回答、测试或规则依据、平台服务证据和教师核验；先闭环再扩展课程覆盖。
