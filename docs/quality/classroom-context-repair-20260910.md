# 课堂上下文与代码示例修复记录

## 复现与原因

用户在课堂输入“给我举一个详细的代码示例”，教师和助教却重复“完整学习闭环”。代码检查确认：这两段文字来自 `_persona_fallback` 的固定降级模板；这类泛指示例请求没有进入承接式检索，前端也没有提交当前板书环节，可能误命中平台介绍。截图足以确认进入了降级分支，但无法据此确定线上降级是网络、配置、配额、模型格式还是审核失败，仍需真实调用轨迹确认。

另发现两个限制：角色回复上限仅 160～220 字符；审核文本清理会合并换行和缩进，破坏多行 Python 代码。

## 修改范围

- 对话请求新增可选 `beat_id`，旧客户端仍兼容。服务端验证环节属于本次课程，并从课程包取得上下文，不接受客户端上传伪造板书。
- 浏览器在当前学生已有课堂记录中选取最近四条和较早的相关问答，最多发送八条，每条最多 1500 字符；脚本化讲授不混入聊天历史。保留角色标签与问答配对，并在服务端省略明显的姓名、学号、电话、邮箱字段。
- 泛指示例、承接追问结合最近有效学生主题或当前课堂主题进行检索；显式新问题仍优先，明确指向板书时才用板书主题。已知无关降级模板不作为检索主题。
- 公开教学示例及逐行解释作为课程证据参与生成和审核；不读取作业答案或隐藏测试。教师、助教、同伴的表达约束保持不同，放宽详细教学的回复长度，但仍有硬上限。
- 对可修复的跑题、漏示例或重复候选最多重新生成一次，重新经过原有审核；安全和答案泄露门禁保留。模型不可用仍显示降级状态，不冒充正常模型回复。
- 文本清理保留 Markdown 代码块的换行与缩进，修复“接口成功但代码不可运行”的问题。
- 官方 Python 文档检索接受已补全的追问主题。进程内页面缓存默认一小时，查询命中缓存最多五分钟、失败/空结果十五秒；限制容量，并合并同页面并发请求。只缓存公共证据，不缓存私人聊天答案。

## 技术参考与边界

参考 [LangChain 官方历史感知检索实现](https://github.com/langchain-ai/langchain/blob/master/libs/langchain/langchain_classic/chains/history_aware_retriever.py) 的“先结合历史形成检索问题，再检索”分层思路。本项目使用有界历史选择和确定性主题补全，复用现有讯飞适配器；没有引入 LangChain 依赖，也没有实现无限长期记忆。

联网仍限制在 Python 官方文档目录白名单内，不是开放全网搜索，不发送完整学生日志给搜索引擎。缓存仅在当前服务进程内共享，服务重启后清空；未新增数据库或 Redis 状态。
